# Rebalancer 3.0.0 – release notes

Packages: `Rebalancer.Core`, `Rebalancer.SqlServer`, `Rebalancer.Redis`, `Rebalancer.ZooKeeper`,
`Rebalancer.Extensions.DependencyInjection` (all 3.0.0).

Change record: [CR-0003](../change-records/CR-0003-release-3-0-0.md). **Read the
[migration guide](migrating-to-3.0.md) before upgrading.**

## Breaking changes

1. **No static provider registry** ([ADR-0013](../adrs/0013-explicit-providers-only-remove-static-registry.md)).
   `Providers` and `new RebalancerClient()` are removed; pass the provider to `RebalancerClient` or use the DI
   extensions.
2. **ZooKeeper requires credentials or an explicit ACL** ([ADR-0011](../adrs/0011-zookeeper-acls-by-default-in-next-major-version.md)).
   The entry points without credentials are removed. The remaining ones throw `ArgumentException` when given neither
   credentials nor an ACL. Keep znodes open deliberately with `ZooDefs.Ids.OPEN_ACL_UNSAFE`.
3. **Redis client records: one hash per resource group** ([ADR-0015](../adrs/0015-store-redis-clients-per-resource-group.md)).
   `RBR:Clients:{group}` replaces the shared `Dictionary:RBR:Clients`. Upgrade all nodes of a group at once; the first
   coordinator moves the group's old entries. Groups no longer read each other's client records.
4. **SQL Server login needs `DELETE` on `RBR.Clients`** ([ADR-0014](../adrs/0014-expire-stale-client-records.md)).
   Without it, coordination keeps working, but stale records are not removed and a warning is logged every heartbeat.
5. **A clean stop deletes the node's own client record** instead of marking it `Terminated` (ADR-0014).

## New

- **Stale client records expire** (ADR-0014). The coordinator deletes records of its group whose last keep-alive is
  older than `ClientOptions.ClientRecordRetention` (default: 10 × the keep-alive expiry period). Age is judged by the
  store's clock, and deletes run only while the coordinator still holds the lease with its fencing token.
- **Automatic re-registration** (ADR-0014). A node whose record was deleted, for example after a very long pause,
  first stops its local activity (`OnUnassignment`), so it can never keep processing reassigned resources, then
  registers again. A coordinator also starts a rebalance.
- `IClientService` (SQL Server, Redis) has two new members, `DeleteExpiredClientsAsync` and `DeleteClientAsync`, with
  default implementations that keep the 2.x behavior for custom implementations.
- Redis ACL users can be limited to one group's client hash.

## Security

- ZooKeeper deployments can no longer be open by accident (TM-0001 residual risk "ACLs stay opt-in" resolved).
- Redis: per-group client keys allow per-group ACLs (TM-0003 residual risk partly resolved; leases and resources stay
  shared).
- SQL Server: the login needs `DELETE` on `RBR.Clients` only (TM-0002 least-privilege guidance to be updated).

## Tests

- New unit tests:
  - expiry requests and default retention (both backends);
  - re-registration stops local activity first (both backends);
  - coordination continues when expiry fails;
  - 3.0 removal contract (`DeprecationContractTests`).
- New integration tests (Docker):
  - Redis expiry under the fencing guard;
  - migration of 2.x entries and group isolation;
  - key escaping;
  - SQL Server expiry and own-record delete.
- Unchanged and passing: Redis and SQL Server assignment safety, and the ZooKeeper single-client, multi-client and ACL
  suites.
