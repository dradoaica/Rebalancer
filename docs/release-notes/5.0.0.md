# Rebalancer 5.0.0 – release notes

Packages: `Rebalancer.Core`, `Rebalancer.LeaseCoordination` (new), `Rebalancer.SqlServer`, `Rebalancer.PostgreSql`
(new), `Rebalancer.Redis`, `Rebalancer.ZooKeeper`, `Rebalancer.Extensions.DependencyInjection`,
`Rebalancer.Extensions.Diagnostics.HealthChecks` (all 5.0.0).

Change record: [CR-0013](../change-records/CR-0013-release-5-0-0.md). Decisions:
[ADR-0029](../adrs/0029-shared-coordination-project-for-sqlserver-and-redis.md),
[ADR-0030](../adrs/0030-postgresql-backend.md),
[ADR-0031](../adrs/0031-valkey-as-a-supported-server-for-the-redis-backend.md). **Breaking change** for code that
uses the SQL Server or Redis service types; see the [migration guide](migrating-to-5.0.md). For SQL Server and Redis:
no behavior, configuration or data format change.
New: a PostgreSQL backend, and Valkey support for the Redis backend.

## One shared coordination package for SQL Server and Redis

The SQL Server and Redis backends had two copies of the same coordination code: leader election under a lease, the
coordinator and follower roles, and the assignment store. Every safety fix had to be made twice. 5.0 moves that code,
unchanged, into the new package `Rebalancer.LeaseCoordination`. `Rebalancer.SqlServer` and `Rebalancer.Redis` depend on
it, so NuGet installs it with them; each backend keeps only its lease, client and resource services.

What hosts see:

- **Most hosts: nothing but a recompile.** A host that creates `SqlServerProvider` or `RedisProvider` from a
  connection string, or registers it with `AddRebalancerSqlServer` / `AddRebalancerRedis`, needs no code change.
- **Code that names the service types** (`ILeaseService`, `IClientService`, `IResourceService`, their request and
  response types, `ClientStatus`, `AssignmentStatus` and others) changes its `using` directives from
  `Rebalancer.SqlServer.*` / `Rebalancer.Redis.*` to `Rebalancer.LeaseCoordination.*`. Each type now exists once
  instead of once per backend. The [migration guide](migrating-to-5.0.md) lists every moved type.
- Libraries compiled against 4.x that use these types must be recompiled (binary break).
- Stored data, the SQL Server schema, the Redis keys, telemetry names and log messages are unchanged.
- ZooKeeper: no change.

## New: PostgreSQL backend

[ADR-0030](../adrs/0030-postgresql-backend.md), [US-0026](../user-stories/US-0026-coordinate-via-postgresql-backend.md),
threat model [TM-0004](../threat-models/TM-0004-postgresql-coordination.md). `Rebalancer.PostgreSql` coordinates
resource groups through a PostgreSQL database, with the same guarantees as the SQL Server backend; it runs on the
shared code above and adds only its services.

- Install the schema with `db/postgresql/RebalanserSchema.sql` and `RebalanserTables.sql`, and give the nodes' logins
  only the role in `db/postgresql/RebalanserLeastPrivilege.sql`: the same three scripts as for SQL Server
  (`db/sqlserver/`). Groups and resources are rows you insert, as on SQL Server.
- `new PostgreSqlProvider(connectionString)`, or `services.AddRebalancerPostgreSql(connectionString)`.
- Uses Npgsql 8.0.9, the last Npgsql line with a `netstandard2.1` build. Telemetry reports
  `rebalancer.backend` = `postgresql`.
- A lease operation locks the group row and reads the database clock after the lock. A node that stalls inside a
  lease transaction is cut off by the server after half the lease expiry, so the others continue.
- Operating guidance (TLS, synchronous replication or a longer lease with standbys, pool size): README, "Operating the
  backends".
- Tested on PostgreSQL 17.8.

## New: Valkey for the Redis backend

[ADR-0031](../adrs/0031-valkey-as-a-supported-server-for-the-redis-backend.md),
[US-0025](../user-stories/US-0025-redis-backend-on-valkey.md). `Rebalancer.Redis` is supported on Valkey 8.1.11 with
no code change: every Redis integration test also runs on it, including the minimal per-group ACL user. Other Valkey
versions are not claimed.

## Upgrading

No data migration. Until the 5.0.0 rollback rehearsal confirms that 4.3 and 5.0 nodes can share a group, upgrade all
nodes of a group at once (see the migration guide, "Upgrading nodes").
