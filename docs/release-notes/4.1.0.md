# Rebalancer 4.1.0 – release notes

Packages: `Rebalancer.Core`, `Rebalancer.SqlServer`, `Rebalancer.Redis`, `Rebalancer.ZooKeeper`,
`Rebalancer.Extensions.DependencyInjection`, and the new `Rebalancer.Extensions.Diagnostics.HealthChecks` (all 4.1.0).

Change record: [CR-0007](../change-records/CR-0007-release-4-1-0.md). Additive only: no breaking API, configuration or
data format change; any upgrade order works.

## Metrics and traces

[ADR-0022](../adrs/0022-rebalancing-telemetry-contract.md), [US-0017](../user-stories/US-0017-emit-rebalancing-metrics-and-traces.md).

Rebalancer now emits metrics and traces through `System.Diagnostics` (no new package; no OpenTelemetry package in the
libraries). Collect them with OpenTelemetry:

```csharp
builder.Services.AddOpenTelemetry()
    .WithMetrics(m => m.AddMeter(RebalancerTelemetry.MeterName))
    .WithTracing(t => t.AddSource(RebalancerTelemetry.ActivitySourceName));
```

| Instrument                         | Type      | Meaning                                                                           |
|------------------------------------|-----------|-----------------------------------------------------------------------------------|
| `rebalancer.rebalances`            | counter   | rebalances run as coordinator; tag `rebalancer.outcome` = `completed` / `aborted` |
| `rebalancer.coordinator.elections` | counter   | this node became coordinator                                                      |
| `rebalancer.assignments`           | counter   | `OnAssignment` raised                                                             |
| `rebalancer.unassignments`         | counter   | `OnUnassignment` raised                                                           |
| `rebalancer.unassigned.duration`   | histogram | seconds from an unassignment to the next assignment                               |
| activity `rebalancer.rebalance`    | trace     | one per rebalance, on the coordinator                                             |

Every measurement carries `rebalancer.backend` (`sqlserver`, `redis`, `zookeeper`, `custom`) and `rebalancer.group`.
The activity also carries `rebalancer.fencing_token` (SQL Server, Redis) or `rebalancer.epoch` (ZooKeeper). Resource
names are never emitted. The names are a contract: they change only in a major version.

## Health check (new package)

[ADR-0023](../adrs/0023-health-check-for-a-rebalancer-client.md), [US-0018](../user-stories/US-0018-report-client-health-to-the-host.md).

```csharp
builder.Services.AddHealthChecks().AddRebalancerClient("rebalancer", client, pendingThreshold: TimeSpan.FromMinutes(2));
```

Pass the client your host started (the DI extensions register clients as transient, so the check cannot resolve it).
`Unhealthy` after an abort or when stopped / not started; `Degraded` while waiting for an assignment longer than the
threshold; `Healthy` otherwise. The check reads state only and never calls the backend.

## Fix: Redis group moved again after a rollback to 3.x

Found while rehearsing the 4.0 → 3.2 rollback. If a group was rolled back to 3.x and its `RBR:Resources:{group}` list
was left in place, the next 4.0.0 start appended the group's resources to that list again, so each resource was
assigned twice. 4.1.0 replaces the leftover list. The rollback steps in [migrating-to-4.0.md](migrating-to-4.0.md) now
delete both per-group keys. Already affected: delete `RBR:Resources:{group}` and re-provision the group's resources.
