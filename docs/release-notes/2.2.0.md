# Rebalancer 2.2.0 – release notes

Packages: `Rebalancer.Core`, `Rebalancer.SqlServer`, `Rebalancer.Redis`, `Rebalancer.ZooKeeper`,
`Rebalancer.Extensions.DependencyInjection` (all 2.2.0).

Change record: [CR-0002](../change-records/CR-0002-release-2-2-0-deprecations.md).

**2.2.0 changes no runtime behavior.** It adds one constructor and marks APIs that 3.0 removes as `[Obsolete]`.
Callers of those APIs get compiler warning CS0618; builds that treat warnings as errors fail until they move to the
replacements below.

## Deprecated (removed in 3.0)

| Deprecated                                                                                  | Use instead                                                                                     | Decision |
|---------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------|----------|
| `Providers` (`Providers.Register`, `Providers.GetProvider`)                                 | `new RebalancerClient(provider)`, or the DI extensions                                          | [ADR-0013](../adrs/0013-explicit-providers-only-remove-static-registry.md) |
| `new RebalancerClient()`                                                                    | `new RebalancerClient(provider)`, or resolve `RebalancerClient` from DI                         | ADR-0013 |
| `ZooKeeperProvider(hosts, …, logger, IZooKeeperService zooKeeperService = null)`            | the overload with `acl, authScheme, authData`; or `ZooKeeperProvider(IZooKeeperService, …)`     | [ADR-0011](../adrs/0011-zookeeper-acls-by-default-in-next-major-version.md), [ADR-0012](../adrs/0012-zookeeper-provider-entry-point-for-a-custom-service.md) |
| `new ZooKeeperService(hosts)`                                                               | `new ZooKeeperService(hosts, acl, authScheme, authData)`                                        | ADR-0011 |
| `AddRebalancerZooKeeper(…, IZooKeeperService? zooKeeperService = null)`                     | the overload with `acl, authScheme, authData`; or `AddRebalancerProvider` with a custom service | ADR-0011 |

**Keeping ZooKeeper znodes open on purpose:** pass `acl: ZooDefs.Ids.OPEN_ACL_UNSAFE, authScheme: null, authData: null`.
This is the same behavior as before, now stated in code. 3.0 keeps this opt-out (ADR-0011).

## New

- `ZooKeeperProvider(IZooKeeperService zooKeeperService, string zooKeeperRootPath, TimeSpan sessionTimeout,
  TimeSpan connectTimeout, TimeSpan minimumRebalancingInterval, RebalancingMode rebalancingMode, IRebalancerLogger logger)`
  for a caller-supplied ZooKeeper service, e.g. a test double ([ADR-0012](../adrs/0012-zookeeper-provider-entry-point-for-a-custom-service.md)).
  A null service throws `ArgumentNullException`. The service handles credentials and ACLs itself; the provider does not
  check them.

## Upgrade notes

- Any upgrade order works: no behavior or data format changes. Redis groups can be upgraded node by node from 2.1.x.
- From 2.0.x, the 2.1.0 upgrade notes still apply (Redis: all nodes at once).

## Coming in 3.0 (decided, not in this release)

- Removal of everything in the table above (ADR-0011, ADR-0013).
- Stale client records expire automatically, and nodes re-register
  ([ADR-0014](../adrs/0014-expire-stale-client-records.md)). The SQL Server login then needs `DELETE` on
  `RBR.Clients`.
- Redis client records move to one hash per resource group, with a migration
  ([ADR-0015](../adrs/0015-store-redis-clients-per-resource-group.md)).

## Tests

- New `DeprecationContractTests`: exactly the members above are `[Obsolete]` (as warnings, naming their ADR), their
  replacements are not, and the ADR-0012 constructor rejects a null service and works with `RebalancerClient`.
- The ZooKeeper integration tests and the example application use only non-deprecated APIs. The few unit tests that
  test a deprecated API on purpose suppress CS0618 locally, with the ADR in the comment.
