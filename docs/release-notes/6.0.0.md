# Rebalancer 6.0.0 – release notes

Packages: `Rebalancer.Core`, `Rebalancer.LeaseCoordination`, `Rebalancer.SqlServer`, `Rebalancer.PostgreSql`,
`Rebalancer.Redis`, `Rebalancer.ZooKeeper`, `Rebalancer.Extensions.DependencyInjection`,
`Rebalancer.Extensions.Diagnostics.HealthChecks` (all 6.0.0).

Change record: [CR-0016](../change-records/CR-0016-release-6-0-0.md). **Breaking changes**; see the
[migration guide](migrating-to-6.0.md). No stored data, key or format change.

## Redis: writes as server-side scripts (ACL step required)

[ADR-0037](../adrs/0037-redis-guarded-writes-as-server-side-scripts.md),
[PRB-0009](../problem-records/PRB-0009-redis-group-does-not-converge-over-a-lossy-link.md). Affects Redis and Valkey.

Keep-alives, leases, assignments and record expiry were optimistic transactions under `WATCH`, which covers a whole
key: any node's keep-alive could make another node's write fail, and over a slow link a group could keep rebalancing
(5.2.0 reduced this). Each of these writes is now a Lua script that checks its condition and writes in one step on the
server, so writes to other fields no longer interfere and a node's writes no longer retry against other nodes'.

What hosts see:

- **A per-group ACL user needs `+eval +evalsha`.** Add them before upgrading the first node of the group (migration
  guide). Scripts run under that user's ACL and reach only its group's keys.
- Groups can mix 5.2 and 6.0 nodes during the upgrade; nothing else changes for Redis hosts.
- A Redis service that forbids scripts cannot run 6.0; stay on 5.2.

## Types no longer public

[ADR-0034](../adrs/0034-public-api-of-the-lease-based-backends-in-6-0.md). The eight types deprecated in 5.2 (warning
RBR0034) are internal: `Rebalancer.LeaseCoordination.Roles.ClientEvent`, `CoordinatorToken`, `EventType`,
`Rebalancer.LeaseCoordination.Store.AssignmentStatus`, `Rebalancer.Redis.ResourceGroup`,
`Rebalancer.Redis.Resources.Resource`, `Rebalancer.Redis.Utils.Constants`,
`Rebalancer.SqlServer.Connections.ConnectionHelper`. A host that built against 5.2 without that warning is not
affected.
