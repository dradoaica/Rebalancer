# Rebalancer 3.1.0 – release notes

Packages: `Rebalancer.Core`, `Rebalancer.SqlServer`, `Rebalancer.Redis`, `Rebalancer.ZooKeeper`,
`Rebalancer.Extensions.DependencyInjection` (all 3.1.0).

Change record: [CR-0004](../change-records/CR-0004-release-3-1-0.md). No API, configuration or data format change; any
upgrade order works.

## Fix: unresponsive followers are told to stop (SQL Server, Redis)

[ADR-0019](../adrs/0019-stop-unresponsive-followers-holding-reassigned-resources.md),
[PRB-0003](../problem-records/PRB-0003-resumed-follower-keeps-reassigned-resources.md).

**Before:** a follower that paused longer than the keep-alive expiry (GC pause, VM freeze, network stall) was declared
dead, and its resources were reassigned. When it resumed, nothing told it to stop, so it kept processing those
resources until the coordinator noticed it again and rebalanced. During that window two nodes processed the same
resource.

**Now:** during a rebalance the coordinator also records "stop" for clients whose keep-alive expired but which still
hold an assignment. A resumed follower stops at its first follower tick, at most the heartbeat period divided by 2.5.

**What this does not fix:** a paused process resumes all its threads at once, including your resource handlers. They
can still run briefly until that first tick. Keep the keep-alive expiry (`LeaseExpirySeconds`) well above the longest
pause you expect. If your resource system can reject stale writers, that is the only way to close the window fully
(see ADR-0019, option C).

ZooKeeper is not affected by this change.

## Documentation

- **Redis ACL:** the minimal command set for a per-group user is now verified, and covered by an end-to-end test:
  `+@read +@write +@transaction +time +echo` with the group's key patterns and `resetchannels` (see the 3.0 migration
  guide).
- The 3.0.0 → 2.2.0 rollback was rehearsed on Redis and SQL Server, for both clean and killed nodes. It works as
  described in the migration guide.

## Tests

- New `UnresponsiveFollowerTests` (both backends): a resumed follower whose resources were reassigned stops once and
  does not restart with them; a non-live client without an assignment is not written again; a failed stop of
  unresponsive clients does not abort the rebalance.
