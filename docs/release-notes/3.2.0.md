# Rebalancer 3.2.0 – release notes

Packages: `Rebalancer.Core`, `Rebalancer.SqlServer`, `Rebalancer.Redis`, `Rebalancer.ZooKeeper`,
`Rebalancer.Extensions.DependencyInjection` (all 3.2.0).

Change record: [CR-0005](../change-records/CR-0005-release-3-2-0.md). No API, configuration or data format change; any
upgrade order works.

## Redis: warning ahead of the 4.0 key layout

[ADR-0020](../adrs/0020-per-group-redis-leases-and-resources.md), [US-0016](../user-stories/US-0016-warn-redis-groups-about-per-group-keys-in-4-0.md).

Every Redis client now logs one warning per session (`IRebalancerLogger.Warn`): Rebalancer.Redis 4.0 moves the group's
lease to `RBR:Lease:{group}` and its resources to `RBR:Resources:{group}`. Nothing changes in 3.2.0. Read
[migrating-to-4.0.md](migrating-to-4.0.md) and update provisioning scripts and Redis ACL users before upgrading to 4.0.
The warning cannot be switched off; it appears once per client start, not per heartbeat.

## SQL Server: least-privilege role script

`db/RebalanserLeastPrivilege.sql` creates the role `rebalancer_node` with exactly the rights a node needs (TM-0002).
Add your nodes' database users to it instead of granting rights one by one.

## ZooKeeper: runbook for securing a group's znodes

`src/Rebalancer.ZooKeeper/README.md` now has a step-by-step ZooKeeper CLI procedure to create a group with the nodes'
credentials, or to secure an existing open group (TM-0001).

## Tests

- Integration tests for a follower paused past its keep-alive expiry and a coordinator stalled past its lease expiry,
  on SQL Server and Redis (PRB-0003, PRB-0001).
- An end-to-end test that nodes whose login has only the `rebalancer_node` role coordinate and clean up.

## Decided, no change

[ADR-0021](../adrs/0021-assignment-generation-for-resource-handlers.md): resource handlers get no fencing token for
now. Keep the keep-alive expiry (`LeaseExpirySeconds`) well above the longest pause you expect, as advised in 3.1.0.
