# Rebalancer 4.2.0 – release notes

Packages: `Rebalancer.Core`, `Rebalancer.SqlServer`, `Rebalancer.Redis`, `Rebalancer.ZooKeeper`,
`Rebalancer.Extensions.DependencyInjection`, `Rebalancer.Extensions.Diagnostics.HealthChecks` (all 4.2.0).

Change record: [CR-0008](../change-records/CR-0008-release-4-2-0.md). No API, configuration or data format change; any
upgrade order works. One behavior change for SQL Server and Redis: see "Aborted state".

## Fix: the health check stayed Unhealthy after a recovered error

[US-0021](../user-stories/US-0021-report-aborted-state-on-sql-server-and-redis.md), [ADR-0023](../adrs/0023-health-check-for-a-rebalancer-client.md)
(note of 2026-10-19).

SQL Server and Redis raise `OnAborted` for every error, also for those they recover from with `AutoRecoveryOnError`.
The 4.1.0 health check treated `OnAborted` as final, so one transient error left a recovered client `Unhealthy` until
the host restarted. The check now clears the abort when the client is assigned again. Upgrade if you use
`Rebalancer.Extensions.Diagnostics.HealthChecks` 4.1.0 with SQL Server or Redis.

## Aborted state (SQL Server, Redis)

A SQL Server or Redis client that gives up after an error (`AutoRecoveryOnError = false`) now reports
`ClientState.Aborted` from `GetCurrentState()` and `GetAssignedResources()`, as the ZooKeeper client always did.
Before, it kept reporting its last state (`Assigned` or `PendingAssignment`).

- `RebalancerClient.BlockAsync` now returns for such a client instead of waiting forever.
- Code that treats every state other than `Assigned` / `PendingAssignment` as "not running" needs no change; code that
  switches over `ClientState` should handle `Aborted` for these backends too.
- When `OnAborted` fires is unchanged: SQL Server and Redis still raise it also for recovered errors.

## Fix: malformed Redis resource entries no longer stop a group

An entry in a Redis resource list that is not valid JSON (an operator typo) made a node fail at start (during the 4.0
key move) or on every heartbeat. Such entries are now skipped; the move logs a warning and leaves them in the shared
list.
